# RCUC20 提示词修复：一次固定快照小试验

完整原始证据见 [v0.32.0 Release](https://github.com/SadPull/LLM-benders-SUC/releases/tag/v0.32.0) 的 `rcuc20-experiments-v0.32.0.zip`。解压后将 `rcuc20/` 下内容恢复到仓库根目录，文中 `results/` 链接即可访问；紧凑结果与图表直接保存在 Git。

**本次新提示词得到 3 个原始可行候选，全部降本、全部零修复；历史第二次调用的 4 个候选均未得到可行方案。** 最佳成本从 3089357.244811 降至 3078300.583061，降低 **11056.661750（0.3579%）**。

## 提示词和反馈修改

- 明确逐小时无条件爬坡公式在启动和停机时也适用；pstart/pshut 是附加容量限制，不豁免 ramp_up/ramp_down。
- 明确初始连续开停时间、跨块状态延续、末小时禁停和末端最小开停窗口截断；要求检查完整机组时间线和替代容量，不能依赖修复实现降本意图。
- 保留完整固定状态矩阵，增加一起始的全天固定开机、固定停机清单；从已提供的 60 条局部梯度中删除 31 条固定开机时段。原 top-20 没有需要删除的条目。剩余梯度仍明确不是可行性证明。
- 用 indexing 明确区分矩阵行列、零起始的 context unit/period/unit_ids，以及一起始的可达性清单和反馈机组/小时；候选说明使用一起始编号。
- 生产反馈保留原始时序中的禁止启停、最小开停时间和末小时违规；连续不可行记录调度状态。这些已知违规不冒充所有修复改动的完整原因。
- 本次任务只提议 u，不允许工具、代码、求解器或额外代理；允许返回少于 4 个候选。

规则明确化和实测评估的组织方式参考 [OpenAI 官方提示词指南](https://developers.openai.com/api/docs/guides/prompt-engineering)。具体约束以本项目代码为准。

## 试验协议

只进行 **1 次新的在线请求**，无重试。沿用历史第 2 次请求的输入、incumbent、base_u、场景、费用、局部梯度及此前反馈；模型仍为 `gpt-6-astra`、`max` 推理，单次上限 1200 秒。基线成本通过当前同一物理模型的连续调度重算。

新请求没有接收历史第 2/3 次回复、参考最优方案或后来 SA 实验的结果；历史第 2 次回复仅在本地作离线对照。没有重跑旧提示词，没有运行 SA，没有调用整数搜索或启动新的下界认证。输入文件 SHA256 与历史记录一致。

这是继承历史快照的候选生成试验，**不是冷启动收敛试验，也不是随机化配对或多次重复的提示词因果验证**。同一模型名并不控制生成波动。

| 指标 | 历史第二次调用 | 本次修改后 |
|---|---:|---:|
| 候选数 | 4 | 3 |
| 固定状态违规位数合计 | 94 | 0 |
| 原始方案物理可行 | 0/4 | 3/3 |
| 修复后物理可行 | 0/4 | 3/3 |
| 新增且改善基线的原始方案 | 0 | 3 |
| 最佳降本 | 0 | 11056.661750 |
| 请求耗时 | 273.61 秒 | 579.51 秒 |

本次耗时约为历史第二次的 2.12 倍。观察到的候选质量更好，但不能直接宣称整体求解效率更高。

| 候选 | 原始方案成本 | 相对同一基线降本 | 修复位数 | 独立物理/费用校验 |
|---|---:|---:|---:|---|
| 1 | 3078300.583061 | 11056.661750 | 0 | 通过 |
| 2 | 3078449.502322 | 10907.742490 | 0 | 通过 |
| 3 | 3079712.845415 | 9644.399397 | 0 | 通过 |

三行降本都是相对同一基线，不能相加。原始与修复后方案完全相同，重复的验证视图也不能计为 6 个候选。三个方案均不同于请求中的 incumbent/base_u。

最佳候选的实际修改（一起始编号）为：1 号第 4–7 小时从停机改为开机；7 号第 7–8 小时改为停机；18 号第 23–24 小时改为停机；19 号第 23–24 小时改为开机。它在可动机组之间协调连续区间和尾部替代容量，没有再尝试关闭冻结机组或启动固定停机机组。最大物理残差为 4.55e-13 MW，最大费用残差为 9.32e-10。

用同一物理模型已有的历史认证 LB=3068326.7015495673 作诊断比较，最佳方案的 gap 约为 **0.3240%**；这不是本次重新计算的下界，且仍未达到 0.1%。本次结果支持继续验证新版提示词，但不证明其能让整套算法在 1800 秒冷启动内达标。
