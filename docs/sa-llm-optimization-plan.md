# SA–LLM 流程优化计划

日期：2026-10-02。状态：正式 Astra 文件模块、自动反馈、无 SA 对照与停滞触发已实现；两轮真实 Astra 闭环验收通过。五组正式性能实验尚未启动。

执行方式已按后续用户要求统一为 Codex 调度的全新 `gpt-6-astra` / `max` 子代理。反馈完全由程序生成；主聊天仅负责调用、等待和回执发布，不补写业务反馈。接口和命令见 [运行说明](astra-module.md)。下文保留研究路线与后续正式实验边界，已有实现以运行说明为准。

## 目标与边界

目标是在保持完整物理验证的前提下，以更少的时间和模型调用达到相同可行解成本。SA 次数是辅助指标，不能代替总成本。相对参考解的成本差与算法自身认证 gap 分开报告。

当前基线为全时域、动态 QUBO、每轮一次 SA 后一次 LLM；LLM 最多输出 4 个完整矩阵，经过修复、去重、局部调度生成割和完整场景验证。Astra 实验由主聊天通过文件交接启动全新子代理，程序自身不会启动子代理。

保留现有默认行为、修复器和完整验证标准。首轮不改退火参数、QUBO 编码、时间分块、输出协议，不增加独立去承诺搜索，不引入并行 LLM。历史归档保持不变，新实验使用新目录。

## 阶段 0：冻结基线与度量

1. 保存源码版本、数据和场景哈希、求解器与模型配置、提示词、初始方案及随机种子。
2. 从已有 Astra 轨迹提取每次 SA/LLM 的新增唯一候选数、修复位数、实测改善、调用耗时、连续求解次数；区分直接刷新最佳解与通过割影响后续搜索，后者不能仅凭来源标签归因。
3. 定义提案 ID 到原始矩阵、修复矩阵、重复目标、可行性和成本的关联。优先复用现有诊断；仅补充缺失字段。
4. 核对已有测试并运行一次基线回归，不重跑昂贵历史实验。实际测试数量以当前检出为准。

验收：旧记录可读；可生成逐调用贡献表；基线测试通过；不向模型提供参考成本、参考调度或评测阈值。

## 阶段 1：增加提案级反馈，保持固定交替

在下一次 LLM 输入中加入上一次调用最多 4 个提案的简明反馈：相对当时最佳解的区间改动、修复改动、重复结果、完整验证是否完成、可行性、总成本和成本分解变化。用稳定提案 ID 关联，不依赖排序位置。

连续不可行的解释只使用真实诊断；未知原因明确为空。被修复后的收益属于修复后的方案，不能归给原始矩阵。候选不必优于最佳解才有反馈。避免把所有历史矩阵重新塞入提示词。

验收测试：改善、无改善、修复、重复、不可行、未完成验证分别正确关联；失败调用不产生虚构收益；关闭增强反馈时保持旧输入语义。离线重放测试验证结构，不能用缓存候选代替新的模型质量实验。

涉及：`suc_benders/context.py`、`llm.py`、`paper_solver.py`，以及相应上下文、解析和主循环测试。

## 阶段 2：补齐无 SA 对照

实现实验专用的 LLM＋连续子问题循环：相同初始化、修复、缓存、完整验证和输入反馈；每次验证后更新最佳解，再请求下一批候选。不运行 SA，不调用其他整数优化器生成候选。

当前 `solve_paper` 明确要求启用 SA，因此不能只把 `quantum_candidates` 关闭就视为有效消融。先复用现有函数实现小型实验入口；只有发现必要重复时才提取共享逻辑，不重写求解框架。

验收：拦截 SA 调用并断言计数为零；同一个固定候选在不同入口的可行性与成本一致；输入不含参考信息。不同组能提供的候选历史自然不同，需记录这种差异。

## 阶段 3：简单的停滞触发策略

引入显式实验开关，默认仍为固定交替。首版策略固定如下，数值作为待验证的初始假设，不宣称最优：

- 初始化后先完成一次 SA，再调用一次 LLM。
- 此后每轮运行 SA；相对该次 SA 前最佳成本，改善达到 0.05% 则清零停滞计数，否则加一。
- 连续 3 次 SA 未达上述改善时调用 LLM；调用结束后清零停滞计数。失败调用也计入调用预算，至少再经过 3 次 SA 才再次触发。
- 不使用 Gurobi 参考值决定何时调用；预算耗尽则停止，保留已完成验证的最佳解。
- 重复率先作为诊断，不在第一版叠加第二套触发规则。

验收：用确定性的模拟成本序列测试首轮调用、停滞触发、改善重置、失败和预算边界；跳过 LLM 不得跳过正常 SA 评估、割更新或历史记录。

## 阶段 4：分阶段对照实验

| 组 | 调度 | 反馈 | 用途 |
|---|---|---|---|
| A | 纯 SA | 不适用 | 保留整数搜索基线 |
| B | 每轮 SA→LLM | 原反馈 | 当前方法基线 |
| C | 每轮 SA→LLM | 增强反馈 | 单独测反馈收益 |
| D | 停滞时调用 LLM | 增强反馈 | 对 C 测调度收益 |
| E | LLM＋连续子问题，无 SA | 增强反馈 | 判断 SA 的增量价值 |

先在历史 10×24 算例做离线和小规模功能试验，再冻结协议，在 RTS-24 确定性和随机场景上验证迁移。RTS-24 已有 SA 基线，但尚不能假定 Astra 在该规模同样有效。不得在看完正式结果后调整阈值并仍称同一验证集。

建议试运行采用种子 7、每组最多 600 秒、LLM 组最多 2 次调用；只检查流程和计时，不能据此宣称效率优势。若预算不足以完成有效调用，记录为未完成，另行修订并冻结正式预算，不混合比较。

正式比较使用种子 7/17/27/37/47，每组同一端到端时间预算，LLM 组同一调用上限；时间预算根据试运行耗时在正式运行前写入协议。模型、推理配置、调用方式和并发度固定。SA 种子配对不等于 LLM 随机性受控，需要报告模型重复运行的不确定性。

Astra 文件交接包含聊天调度与等待；分别报告端到端时间和可观测分项，不把无法测得的纯推理时间或 token 数估成精确值。自动 API 与子代理结果分开比较。若无法保证可比计时，先作同调用预算的候选质量实验，不宣称速度优势。

主指标：同预算下最终可行成本、到达预注册成本阈值的时间和成功率。辅助指标：SA/LLM/连续求解次数、有效唯一候选率、修复幅度、真实 token/费用（若可得）。未达标作为未达标报告，不仅对成功样本求平均。

参考阈值建议为相对独立参考成本 +5%、+2%、+1%、+0.5%、+0.1%，仅评测端使用。报告参考求解状态和下界；目标不可达时也不能事后删除。算法自身下界不可得的组标为不可得。

决策：C 对 B 验证反馈，D 对 C 验证调度，E 对 C 验证是否仍需要 SA。优先比较可行解质量与资源消耗的共同改善；若出现时间与质量权衡，报告权衡，不用单个综合分数掩盖。五个种子只作初步证据。

## 后续候选，不纳入首轮实现

1. 区间修改输出与多样化候选：仅在重复或修复损失确实显著时实施；保留完整矩阵作为对照。
2. LLM 优质方案附近的 SA 搜索或热启动：先核对 SDK 能力及辅助变量编码；保留全局探索，不能只用局部邻域宣称同等搜索范围。
3. 复用连续求解结果：先证明目标、约束、场景、精度与对偶语义一致，再做复用；不删除完整验证。

## 下一次实施的交付范围

首先完成阶段 0 和阶段 1：贡献审计、最小反馈字段、针对性回归测试和离线重放。通过后再实现无 SA 对照与停滞调度，最后开展真实模型试运行。每一步独立验证，不同时改变提示词、调度、输出格式和 SA 参数。

本轮实施完成两次真实子代理验收调用，未启动正式性能实验、后台自动化、提交或推送。
