# RTS-24 正式补跑（账户认证路径）

补跑 C/17、D/7、C/27、D/17，按此预定顺序串行执行。用户批准本次总共最多 16 次 Astra/max 调用：前两次启动尝试的 4 次失败单独保留在 `../rts24-recovery-20261004/` 和 `../rts24-recovery-20261004-fixed/`，此目录的四项正式补跑最多使用 12 次调用。

求解源码、输入和依赖沿用原批次的冻结快照，各次预算 1800 秒，从初始化计时。每次最多三次全新 Astra/max 会话，每次最多四个候选。C 用完额度结束；D 在 LLM 调用之后继续 SA 至截止。原始参考解复核后复用，不进入搜索或模型输入。

独立 Python 后台程序调用 `codex exec --ephemeral`，显式使用已登录账户和系统代理；仅在子进程中移除会覆盖账户认证的环境变量，未修改用户凭据和全局配置。模型只授权读取对应调用的 `system.txt`、`user.txt`，以及写入 `candidates.json`。生成候选不调用求解器或参考结果。

后台根据真实会话 ID、`turn.completed` 事件、进程成功退出和原始候选文件签发回执；原始输入输出保持哈希检查。认领、模型等待及交接均计入预算。到期终止活跃模型会话，不接收迟到输出；调度会话失败时保留现场并停止后续运行，避免自动耗尽额度。

原最小必要性批次和两次旧补跑不覆盖。新的四项预先指定替换原分析集相同的组别/种子，其余 11 项复用原分析结果；全部失败和旧结果都保留。新旧日期和调度环境不同，达标时间存在混杂。数值审计与模型响应是否完整分别报告。

- `manifest.json`：授权、调用总额、固定顺序、原始文件及失败尝试哈希、源码/输入/控制程序指纹、验证记录。
- `state.json`、`controller.*.log`：后台进程、当前运行和控制日志。
- `C-17/` 等：事件、检查点、逐级候选质量、物理审计和最终结果。
- `calls/*/agent-events.jsonl`：独立模型会话的真实工具及完成事件；`agent-completion.json` 保留实际返回的用量。
- `report.md`、`summary.json`、`curves.csv`：每项结束后自动更新，四项结束后生成最终验收。

查看即时状态：

```powershell
python experiments/rts24-recovery-20261004-account/orchestration/status.py
```

如需主动取消，在此目录创建内容为 `{}` 的 `cancel.json`。程序终止模型会话，向求解器发出取消信号，保留已验证检查点，并停止后续运行。电脑关闭或后台进程被外部终止仍可中断执行，记录会保留。

勿在此目录启动第二个控制程序。`--prepared --resume` 仅跳过已正常结束的搜索，不能重发已认领的请求或把旧运行恢复为新的时间预算。复现实验使用新输出目录及本批次冻结的求解源码。
