# RTS-24 中断实验补跑

**本目录为已停止的后台启动尝试。** 仅 C/17 启动过，三次调用均因连接或认证路由失败而未获得候选；其他三项未启动。用户随后批准总额度增至 15 次，修正系统代理和账户认证路径后，四项正式补跑另存于 `../rts24-recovery-20261004-fixed/`。本目录不作为正常的 LLM 能力测量，失败及耗时保留。

本批次补齐原最小必要性实验的四项模型交接缺失：C/17、D/7、C/27、D/17。用户于 2026-10-04 请求补跑，并明确选择独立后台 Astra/max 子代理调度；本批次额外最多 12 次模型调用。

四项按上述顺序串行运行，各次预算 1800 秒、最多三次全新 Astra/max 会话、每次至多四个候选。C 用完调用额度结束；D 继续 SA 至截止。算法、数据和修复/验证程序使用原批次完整的冻结源码与依赖版本。

本次修改了调度方式：独立的 Python 控制程序通过 `codex exec --ephemeral` 创建模型会话，使用原来的 `subagent.claim` 指令和 `subagent.receipt` 回执。请求认领、模型等待、文件工具和交接均计入预算；候选文件存在不足以签发回执，必须收到真实 `turn.completed` 事件且进程成功退出。到期关闭活跃会话，迟到输出不回传。

原批次目录和压缩包保持原样，旧失败与部分结果均保留。补跑的四项预先指定，不根据新旧成本选择较好结果；最终分析使用这四项的新结果，以及原分析集其余 11 项。新旧调度环境和日期不同，达标时间不能当作无混杂的算法速度比较。

- `state.json`：后台控制程序状态和当前进程。
- `manifest.json`：授权、固定顺序、原文件哈希、源码/输入快照、控制程序版本、参考结果哈希和 108 项回归验证记录。
- `snapshot/`：原实验源码、测试和 RTS-24 数据；模型只授权读取本次调用的两个输入文件。
- `C-17/` 等：完整事件、检查点、结果、逐级候选统计和物理审计。
- `calls/*/agent-events.jsonl`：真实模型会话 ID、工具操作和完成事件；`agent-completion.json` 记录实际返回的用量，未知字段保留为空。
- `report.md`、`summary.json`、`curves.csv`：每项结束后自动更新；全部完成后自动生成最终审计。

控制程序独立于聊天执行；电脑关机、进程被外部终止或服务不可用仍会留下中断记录。发生失败时停止后续搜索，保留现场，不自动重试已认领的请求。

如需主动取消，在本目录创建内容为 `{}` 的 `cancel.json`；控制程序终止当前模型会话，向求解器发出取消信号，保留已验证检查点，并停止后续运行。

查看状态后再决定是否需要新的尝试。勿在此目录启动第二个控制程序。复现实验应使用新目录：

```powershell
python -m suc_benders.recovery_experiment --output-dir experiments/rts24-recovery-new --codex <codex.exe 的绝对路径>
```
